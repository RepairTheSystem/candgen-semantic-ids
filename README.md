# Кандген для маркетплейса с повторами: семантические ID против dense и истории

Продолжение [repeat-switch-rec](https://github.com/RepairTheSystem/repeat-switch-rec) (одностадийная модель
с переключателем «повтор / новое» на синтетике). Здесь — этап кандидатов на реальных данных Instacart, где полный softmax
по каталогу и «все в одной модели» уже не бесплатны.

Генеративный ретривал по **семантическим ID** (TIGER → OneRec, PinRec, Sona) заменяет ANN-индекс генерацией токенов товара.
По свежим работам SID сильнее там, где нужно обобщение, а item-ID модели — где нужно запоминание; в маркетплейсе повтор —
запоминание, новое — обобщение.

**Гипотезы.** H1: SID-ретривал лучше dense на новых товарах и особенно на хвосте. H2: переключатель между источниками
на запрос (сколько из K слотов отдать истории) лучше фиксированной квоты.

## Источники кандидатов

| источник | что делает |
|---|---|
| `hist+pop` | товары истории с затуханием по заказам, остаток — популярное (классика next-basket) |
| `dense` | SASRec-энкодер + dense-ретривал, sampled softmax, точный MIPS |
| `sid-text` / `sid-cf` | SID из текста товара (TF-IDF → SVD → residual k-means) или из эмбеддингов dense-модели; декодер + constrained beam search |
| `hybrid-*` | кандидаты SID → доранжирование dense-скором (LIGER-подобно) |
| `union[…]` | K слотов: q из истории + (K − q) нового; q фиксирован (подобран на val) или предсказан на запрос |

Энкодер у dense и SID одинаковый, `-exp`-источники исключают всю историю пользователя.

**Протокол:** test — последний заказ пользователя, val — предпоследний; ранняя остановка по val Recall@50.
**Метрики:** Recall@K, микро-Recall по повторам, новому и новому из хвоста (вне топ-20% по частоте), coverage@100,
латентность одного запроса.

## Результаты v1 (Kaggle GPU, 1 сид)

28 667 пользователей, 24 149 товаров, средняя тестовая корзина 10.4 товара, 61% товаров корзины — повторы.

| источник | R@10 | R@50 | R@100 | R@200 | explore@100 | explore-tail@100 | coverage@100 |
|---|---|---|---|---|---|---|---|
| hist+pop | **0.352** | **0.585** | **0.644** | **0.685** | 0.096 | 0 | — |
| dense | 0.159 | 0.315 | 0.404 | 0.502 | 0.171 | **0.0147** | **0.79** |
| sid-text | 0.143 | 0.285 | 0.366 | 0.455 | 0.175 | 0.0030 | 0.31 |
| sid-cf | 0.138 | 0.280 | 0.363 | 0.457 | 0.179 | 0.0022 | 0.29 |
| hybrid-text | 0.152 | 0.308 | 0.396 | 0.489 | **0.189** | 0.0053 | 0.32 |

**Выводы**

1. **История — главный источник:** `hist+pop` при K=10 дает в 2.2 раза больше dense. Это согласуется с
   [A Next Basket Recommendation Reality Check](https://arxiv.org/abs/2109.04584); обученные источники нового лишь
   на ~25% лучше популярного.
2. **H1 отвергнута в части хвоста.** На новом в целом SID чуть лучше dense, но на хвосте в 5–7 раз хуже, coverage
   в 2.5 раза ниже: beam search тянет к популярным кластерам. Гибрид поднимает общий Recall SID, но хвост почти не лечит.
   Зато у SID в 6 раз меньше параметров (285 тыс. против 1.66 млн — нет таблицы эмбеддингов товаров).
3. **H2 проверять нечего:** подобранная квота почти везде q = K (сначала вся история), переключатель вырождается в то же.
   Слот истории в разы «дороже» слота нового, а истории (медиана 47 товаров) хватает на почти все K ≤ 50.
4. **Ошибка постановки:** «oracle» с q = K · доля повторов — не верхняя граница (хуже `fixed`): решает вероятность
   попадания на слот, а не доля. Честная граница — лучший q для каждого пользователя.
5. **Латентность (GPU, batch=1):** hist+pop 0.6 мс, dense 2.4 мс, SID beam 200 — 10.2 мс (×4.3), гибрид — 12.9 мс.
   На 24 тыс. товаров точный MIPS почти бесплатен; на больших каталогах соотношение будет другим.

## Запуск

```bash
pip install -r requirements.txt
python run.py --fake                                     # дымовой прогон на фейковых данных формата Instacart
python run.py --data-root <папка с csv Instacart> --n-users 30000
```

## Файлы

`instacart.py` — данные и протокол · `semantic_ids.py` — построение SID и префиксное дерево ·
`models.py` — энкодер, `DenseRetriever`, `SIDRetriever` · `run.py` — обучение, источники, метрики, латентность, отчет.
